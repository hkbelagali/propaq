    Changelog¶

    All notable changes to this project will be documented in this file.

    The format is based on Keep a Changelog.

    [Unreleased]¶

    Changed¶

    • crates/core/src/soa/ is deleted. The merge-then-sweep engine has no remaining caller: the surrogate was its last one and now builds on the partitioned engine. What it owned that was not the engine has been re-homed rather than dropped: its row storage becomes crates/core/src/store/ (TermSum, TermBasis, sparse.rs), which is what PauliTermSum/MajoranaTermSum and hybrid::contract consume; SoaPropagator's surviving half becomes RunConfig (the pool, the noise model, the truncators and the log settings a propagator holds between calls); and NoiseDispatch moves to engine_noise.rs, next to the table it resolves into. Roughly 2900 lines of kernels go with it.
    • Requests past the width ladder now raise ValueError naming the limit, where they used to fall through to SoA. There is no second backend to fall back to, so a silent slow path would be worse than a clear refusal.
    • filename= on expectation_value is served by the partitioned engine, which had previously been excluded from the fast path for it. It asks the run for its terms and writes them through the same save_terms_to_file as propagate.
    • The 120-row behaviour snapshot (tests/oracle/) is unchanged by the surrogate port and the SoA deletion, which is the intended result: both are structural.
    • build.sh resolves the target interpreter before module purge. The purge unloads the Miniforge module along with everything else, leaving python3 as the system 3.10, so the script had been building an extension for an ABI the calling Python would never import: the tree looked rebuilt while the previous .so stayed live. It now pins PYO3_PYTHON, names the destination from the same interpreter, and lists any extension present for another ABI.
    • The width ladder reaches 2048 units, up from 256, so wide circuits no longer fall back. Verified bit-identical across every arm: the same 8-qubit-support circuit embedded in 16 to 1600 qubits gives 8544 terms and the same expectation to 15 digits at W = 1, 2, 4, 8, 16, 32 and 64. Workspace build time goes from about 1m20 to 2m10.
    • Verbose logging works on the partitioned engine, reusing the existing schema so LogParser consumers keep working. Two fields change meaning and the event now says so, via a new truncation_model field: terms_discarded counted terms a sweep removed from the live set, and now counts branches the emit gate refused before the term existed; outbox_terms measured the emitted-but-not-yet-deduplicated backlog, which cannot exist when duplicates are folded on insert, so it is always zero. discarded_coeff_l1/max are reported as zero rather than fabricated: producing them would mean accumulating over every declined branch during the scan (billions on a deep circuit) and would measure refused branches rather than removed terms. With log_every > 1, avg_ms_per_gate is that gate's elapsed time rather than an average since the last record.
    • The surrogate builds on the partitioned engine. crates/surrogate/src/engine.rs propagates SymbolicCoeff through the same store, exchange and Clifford tableau as a numerical run; only the truncation differs, and deliberately: frequency, monomial budgets and simplification are properties of an accumulated symbolic coefficient, so they stay a post-accumulation pass rather than moving to the emit gate, which would be gating on the wrong thing. EmitCutoff is left empty there for that reason.
    • The engines are generic over CoeffRepr::GateParam, not just f64, so a symbolic parameter index reaches them the same way an angle does.
    • PartitionedOperator gained the primitives the surrogate needs: with_coeffs_mut (a partition is already one shard), sum_coeffs, retain (the general form of reclaim, for a predicate about structure rather than magnitude) and map_partitions.
    • map_partitions hands the Clifford tableau over with each partition. Stored keys are pre-conjugation, and a consumer reading rows directly has to apply the frame or it sees the wrong operator and loses the sign. The surrogate's compile pass did exactly that at first, and the from-qiskit agreement tests caught it.
    • The partitioned engine is propaq's numerical backend. PROPAQ_ENGINE is gone; both PauliPropagator and MajoranaPropagator serve propagate and expectation_value from it, for both bases and both coefficient widths, with noise and the full truncation pipeline. Results move: it gates a term when the term is emitted where the SoA engine created it and swept afterwards. Measured across a 120-configuration matrix, 110 are numerically unchanged and 10 trace to two identified semantic differences (the emit gate, and the observable's own terms now facing the cutoff before the first gate rather than after it).
    • propagate returns the evolved operator from the engine's own store, via RunOutput, with the deferred Clifford tableau applied on the way out. filename= writes from the same materialization.
    • Every experimental engine flag is gone: PROPAQ_ENGINE, PROPAQ_PAIR_RULE, PROPAQ_NO_PRECHECK, PROPAQ_NO_BROADCAST, PROPAQ_PARTITIONS, PROPAQ_INLINE_POSITIONS. The precheck and the pinned broadcast dispatch are unconditional (both are bit-exact and were only ever switchable for an A/B), and the partition count follows the pool.
    • PROPAQ_PHASE_TIMES is now a log event. A run with a Logger attached writes one closing engine_phases record with the scan/absorb/claims split, per-phase pool occupancy, the inline width the store settled on, and the visited/emitted/declined/exchange-hit counters, surfaced as LogParser.engine_phases_events. It replaces the env-var eprintln!, which only covered the Pauli path and could not be read from Python at all.
    • progress_bar is accepted and inert. The engine runs its gate loop with the GIL released and cannot drive a tqdm bar from inside the pool; the constructor argument stays so existing callers keep working, and the docstring says so rather than leaving a silently dead option.
    • PROPAQ_NO_PIN is now a pin_threads: bool = True constructor argument on both propagators, documented together with the threaded-BLAS interaction that makes pinning a large loss rather than a large win.
    • The inline row width adapts. It starts at the measured knee (24 positions) and PartitionedOperator::repack_if_overflowing widens it when more than 20% of rows have spilled, which removes the depth-sensitive constant without giving up the tuning: starting narrow and growing into it was tried and measured 2.47s against 1.84s at 6x6 Ising-Trotter step 19.
    • Deleted: crates/core/src/clifford_frame.rs (superseded by tableau.rs and already unwired) and Operator::is_pending.
    • The partitioned engine applies noise. All three NoiseDispatch arms are functions of term weight alone, so engine_noise::resolve_noise_table collapses each to one table built with the GIL held and read inside the pool; a Bound<PyAny> is not Sync and cannot cross into rayon at all. Behaviour change for custom Python noise models: they are now called once per distinct weight rather than once per term, which is identical for any model honouring the documented contract and faster.
    • PartitionedOperator::reclaim rebuilds each partition from the terms the cutoff still admits, and the engines run it after every noise layer. The store is otherwise append-only, so a coefficient that only shrinks after the fact never gets reconsidered: damping would fill the store with terms far below the cutoff, still scanned and still resident. Exchange-free and fully parallel, since a surviving term already sits in the partition that owns it. InvertedIndex::reset exists for the same reason: it is incremental against a store that only grows, and reclaim moves rows.
    • PartitionedOperator::scale_by_weight (and a serial fallible form) is the primitive underneath, and is the shape any damping channel needs.
    • The pair rule is unconditional and no longer reachable as a switch: EmitCutoff::rescue_pairs and PROPAQ_PAIR_RULE are gone, and monoprop's rule is simply the engine's truncation semantics. The A/B tests that toggled it are replaced by the three unit tests that pin the rule itself.
    • The emit gate now carries the whole resolved truncation pipeline rather than two bounds. NativeTruncator decides per term through EmitCutoff::admits_child, replacing the weight and coefficient bounds as it does in the SoA kernels, and disabling the precheck (an opaque predicate over the child's weight cannot be predicted from its source). TermBudget::min_terms suppresses every lossy predicate while the operator is below the floor, resolved once per gate against the whole operator rather than per partition.
    • FlushSchedule has no meaning for the partitioned engine, which folds duplicates on insert and so has no outbox to flush. It is accepted and ignored rather than rejected, and documented as such.
    • Fixed: the partitioned engine silently ignored noise. Behind PROPAQ_ENGINE=monoprop a noise model was accepted and then dropped, returning the noiseless expectation value; an 8 to 16 qubit sweep came back bit-identical with and without UniformNoiseModel(0.05). Caught by the behaviour snapshot before the engine became the default, and fixed by implementing noise rather than by declining.
    • Fixed: f32::magnitude returned a signed value, not an absolute one, so every negative coefficient compared as below any threshold. Latent until now (the ordinary cutoff goes through passes_coeff_cutoff, which was correct); reachable through NativeTruncator and terms_below, and it would have broken the emit precheck the moment f32 reached the partitioned engine. The trait now documents the contract.
    • Majorana runs on the partitioned engine. crates/majorana/src/algebra.rs implements Algebra<W> over the interleaved monomial, and crates/majorana/src/engine.rs is its width dispatch. The Jordan-Wigner parity plane p is not stored: it is a function of modes (key_hash/key_eq already read modes alone), so it is recomputed inside weight, which only runs under a structural cutoff. The key stays one bitset wide.
    • Odd-length Majorana generators keep the inverted index. Their anticommutation test carries the term's own key parity, which the transposed columns cannot express, so such a gate previously fell back to a parity computation per live term. InvertedIndex now keeps a row-parity column and apply_row_parity folds it in. Disabling it makes the differential test diverge immediately (283 terms against 2344), so the path is covered rather than merely present.
    • The engine is generic over CoeffRepr, so f32 term sums no longer fall back to SoA. New CoeffRepr::sin_branch_magnitude computes the predicted branch magnitude in the representation's own precision, which is what keeps the emit precheck bit-exact for f32 as well as f64: widening to f64 and multiplying there would round once where the branch rounds twice.
    • Algebra::weight and Algebra::trace take n_units, as SoaBasis already did. A Pauli's weight is its support and ignores it; a Majorana's is the weight of its Jordan-Wigner image, whose Z-string runs to the end of the register.
    • The emit cutoff now applies to an observable's own terms, through EmitCutoff::admits_initial. They reach the store through add rather than through a rotation and so never faced the gate, which let a term the cutoff excludes sit in the store forever. Note this still diverges from SoA, which pruned post hoc and so let an over-weight initial term spawn descendants during the first gate before removing it.
    • The monoprop-shaped engine's partitions are now pinned to workers and workers to cores, instead of being handed out by rayon's splitter each gate. rayon::broadcast gives partition i a stable worker i, and the propagator's pool pins worker i to the ith CPU in the process's affinity mask. A partition's store fits a core's private cache, which only pays if the same core keeps serving it; before this, a partition changed core from gate to gate and total CPU roughly doubled between 1 and 64 workers. Term counts and expectation values are unchanged, being scheduling-only changes.
    • The absorb phase prefetches over one stream spanning every inbox addressed to a destination, rather than one group per inbox. S partitions fragment a gate's emissions into S*S inboxes (under three messages each at 64 partitions), which stopped the prefetch group filling exactly where the store stopped fitting in cache.
    • Together, on 6x6 Ising-Trotter step 13 at a 1e-6 cutoff: 2.09x behind monoprop to 1.01x at 32 threads, and 2.27x to 0.98x at 64.
    • The scan declines a rotation's sine branch before forming it. Its magnitude is |source| * |sin(theta)|, which needs neither the source's key nor the child's, so the row read and the product that used to precede the cutoff test are skipped for a branch that cannot survive it. On 6x6 Ising-Trotter step 21 the scan reaches 4.8 billion rows and keeps 24% of them, so three quarters of the products it formed were discarded; deeper circuits kept a smaller share, which is what made the scan look like it degraded with depth when its cost per visited row was in fact flat. Results are bit-for-bit unchanged: an anticommuting product's phase is exactly +-i, so the hoisted test rounds identically.
    • sin_cos is computed once per gate rather than once per term, via the new CoeffRepr::rotation_factors and CoeffRepr::apply_rotation_with. The angle is fixed for the gate, so this was billions of transcendental calls on a deep circuit.
    • The pair rule runs on the precheck too. A held-back branch's value is source * sin(theta) * (-phase.im), and only the phase needs the product, which drain_claims was already re-forming and discarding; so the decline records source * sin(theta) and the claim multiplies in the phase. Bit-identical, and branches that are never claimed never form a product. Operator::pending_needs_phase tracks which convention a gate used. The write-only pending_admitted column is gone.
    • The pair rule's rescue round costs one synchronization point instead of two. A claim is recorded on the partition doing the absorbing, so the drain runs at the tail of the absorb pass rather than behind its own barrier; it writes to a separate rescue_outboxes buffer, since peers may still be reading outboxes[self][peer]. Rescue-round wall time at step 21 halved, 1.497s to 0.749s, and PROPAQ_PHASE_TIMES=1 now reports it separately.
    • Together these make the pair rule the faster setting at depth as well as the accurate one: against monoprop at 64 threads it goes 1.61x to 1.07x at step 21 and 1.49x to 0.96x at step 19, holding monoprop's term count to within 1%. It also overtakes propaq's own rule at step 21 (5515 ms against 5869 ms) by doing 40% less work and no longer handing the saving back at the barriers.
    • Together on step 21 at 64 threads: scan CPU 341.9s to 141.6s, wall 12.5s to 7.7s. Against monoprop, step 19 goes 1.71x to 1.20x and step 21 2.00x to 1.40x. Per term propaq is now faster than monoprop (0.81x and 0.87x); the remaining wall-clock gap at depth is the truncation rule keeping more terms, not the kernel.
    • TermSum (then SoaTermSum) now stores term keys sparsely: each row is the sorted list of positions of its set bits (plane * stride * 64 + word * 64 + bit), held in a new store::sparse::SparseRows row store, replacing the persistent [Vec<u64>; 2] dense word planes. Coefficients, merge hashes, and the sparse rows are compacted together, so no offset ever survives into a stale position arena. Numerical behavior is unchanged for Pauli, Majorana, and surrogate propagation.
    • TermBasis (then SoaBasis) gained sparse counterparts to its word-plane methods (weight_sparse, trace_sparse, key_hash_sparse, key_eq_sparse, commutes_sparse, product_sparse). PauliBasis and MajoranaBasis implement them directly on position lists; the defaults decode a single row and delegate, so other bases keep working unchanged.
    • Removed the dense term-plane accessors TermSum::plane, term_plane, and term_planes. Export boundaries that must rebuild an owned PauliString/MajoranaMonomial use TermSum::decode_row into a caller-owned one-row buffer instead.

    Added¶

    • crates/core/src/affinity.rs: CPU pinning for pool workers, reading the process's own affinity mask so a run under taskset, numactl or a cgroup uses the cores it was given. Linux only; a no-op elsewhere. Controlled by the pin_threads constructor argument.
    • PROPAQ_PHASE_TIMES=1 now also reports per-worker busy time and pool occupancy per phase (PartitionedOperator::phase_busy_seconds), which is what separates load imbalance and barrier cost from the cost of the work itself. Release builds inline both phases into one rayon closure, so a profiler cannot recover this.
    • Note for embedders: pinning makes threaded BLAS actively harmful, because a pinned worker cannot step around a spinning BLAS thread. qiskit loads two OpenBLAS copies, each starting one spinner per core. Set OPENBLAS_NUM_THREADS=1 (and OMP_/MKL_) before numpy imports; measured 449ms against 184ms at 64 threads without it.
    • store::sparse::DenseWorkspace: an explicitly-owned, chunk-bounded dense workspace, the only place word planes are materialized. It is never stored in a TermSum, never returned by a public API, and never outlives the kernel call that borrows it.
    • Storage accounting: TermSum::sparse_key_bytes (resident keys only) and propaq._rust_core.workspace_peak_bytes() (temporary-workspace high-water mark), also reported on PropagationResult as sparse_key_bytes and workspace_peak_bytes.
    • crates/pauli/tests/sparse_dense_equivalence.rs and crates/majorana/tests/sparse_dense_equivalence.rs: sparse-vs-word-plane differential tests for the basis methods, plus randomized multiword circuits (duplicate merges, compaction holes, Clifford and non-Clifford rotations) run under both kernel layouts.

    [0.1.2] - 2026-07-31¶

    Added¶

    • Arbitrary Qiskit gate support in PauliCircuit.from_qiskit, MajoranaCircuit.from_qiskit, SurrogatePauliCircuit.from_qiskit, and SurrogateMajoranaCircuit.from_qiskit. Gates outside the native rotation basis (xx_plus_yy, p, rz, rx, ry, cp, x, swap) are now decomposed via Qiskit's transpiler into that basis instead of raising, via a new shared dispatch module propaq/circuits/_gates.py. Emits a UserWarning naming the gate and the resulting rotation count, since decomposition cost varies a lot by gate.
    • rx/ry added to the native rotation basis, closing the basis under Qiskit's standard ZXZ Euler decomposition and letting the transpiler-based fallback reach essentially any 1- or 2-qubit gate, and multi-qubit UnitaryGates, without it.
    • Random-Qiskit-gate test coverage: tests/circuits/test_arbitrary_gates.py, tests/propagator/test_loschmidt_random_gates.py, and random-arbitrary-gate coverage added to tests/circuits/test_surrogate_from_qiskit.py.
    • Optional Cirq support, mirroring the Qiskit architecture: from_cirq on PauliCircuit, MajoranaCircuit, SurrogatePauliCircuit, and SurrogateMajoranaCircuit, gated behind a new cirq extra (pip install propaq[cirq]).
    • Persistent, open-addressed hash table for merging
    • Hybrid Schrodinger-Heisenberg simulation of expectation values via hybrid_expectation_value.
    • Custom gate registry for user-defined gates, with internal validation against native decomposition.

    Fixed¶

    • MajoranaTermSum._xx_plus_yy_terms's relative sign between its two Majorana monomials was computed with period 2 in the qubit gap (1 if d % 2 == 1 else -1), but the correct sign (from reordering the JW string into canonical bit order) has period 4. This gave us the wrong sign for XXPlusYYGate(theta, beta) on non-adjacent qubits with beta != 0 at gaps d % 4 in (2, 3).
    • MajoranaTermSum.from_swap had the analogous bug, but distributed differently across its three monomials.

    Changed¶

    • Add hydrogen chain benchmarks and remove old stale benchmarks.
    • .github/workflows/benchmarks.yml: the ASV (Python) benchmark job now runs unconditionally on every PR push, instead of only when the PR is labeled benchmark. The Criterion (Rust) job now also runs automatically on every push to main (post-merge tracking), in addition to its existing PR label.

    [0.1.1] - 2026-06-29¶

    Added¶

    • Added timing information to logging output, which prints the average time taken for each gate application and the total time taken for the truncation.
    • Updated README.md with initial_state parameter in the expectation_value method of MajoranaPropagator and PauliPropagator classes, replacing the deprecated fock_state.
    • qiskit_gate_idx field in JSONL log output for both gate and truncation events. Each event now reports the index of the originating Qiskit gate so log data can be mapped back to specific positions in the source circuit. Multiple propaq rotations that expand from a single parameterized Qiskit gate share the same qiskit_gate_idx. Circuits not constructed via from_qiskit emit null for this field.
    • Test suite for logger/log-parser integration under tests/log/, covering Qiskit-sourced circuits, truncation events, and directly constructed circuits.
    • to_sparse_pauli_op() method on MajoranaTermSum and PauliTermSum to convert back to a Qiskit SparsePauliOp.

    [0.1.0] - 2026-06-27¶

    Changed¶

    • BMI2 PEXT optimization for compress_to_qubits in MajoranaMonomial, we can use _pext_u64 via runtime CPU feature detection, extracting qubit bits from mode bitsets in ~2 instructions per 64-qubit word instead of a scalar bit-loop. Falls back to the scalar path on non-BMI2 hardware.
    • Replaced XOR-fold partition_key with FxHash in MajoranaMonomial and PauliString. The XOR-fold produced high collision rates for large workloads, permanently pinning terms to the same partition regardless of thread count.
    • Parallelized initialize_from in AbstractPropagator: a sequential pass buckets each term by its owner partition, then each Rayon worker fills its own FxHashMap in parallel. Each worker first touches its own map, which helps for NUMA locality.

    [0.1.0] - 2026-06-26¶

    Added¶

    • WeightCutoffExtrapolator and CoefficientCutoffExtrapolator classes implementing Zero-Cutoff Extrapolation (ZCE) by sweeping weight and coefficient truncation cutoffs respectively, then fitting with a user-supplied function via scipy.optimize.curve_fit.
    • ZCEResult dataclass holding the extrapolated zero-cutoff value, the sweep data, and the fit parameters and covariance matrix.
    • noise property and set_noise() method on AbstractPropagator, MajoranaPropagator, and PauliPropagator to allow dynamic swapping of the noise model between runs.
    • truncation property and set_truncation() method on AbstractPropagator, MajoranaPropagator, and PauliPropagator to allow dynamic adjustment of truncation policies during propagation.
    • Test cases for WeightCutoffExtrapolator and CoefficientCutoffExtrapolator classes to validate their functionality and ensure correct extrapolation behavior.
    • Example notebook demonstrating the usage of ZCE on a hydrogen chain.

    Changed¶

    • AbstractPropagator abstractmethods for consistency with concrete implementations.
    • Register PauliPropagator and MajoranaPropagator classes as subclasses of AbstractPropagator to enforce the implementation of required methods.
    • noise and truncation constructor parameters in MajoranaPropagator and PauliPropagator stubs now use concrete types (UniformNoiseModel | GateNoiseModel | None and TruncationPolicy | None) instead of object | None.
    • GateNoiseModel.apply_noise stub now accepts MajoranaTermSum | PauliTermSum instead of object.

    Fixed¶

    • Renamed fock_state parameter to initial_state in the expectation_value method of both PauliPropagator and MajoranaPropagator classes for API consistency for use in Zero-Cutoff Extrapolation (ZCE) and Zero-Noise Extrapolation (ZNE) methods.
    • Fix ZeroNoiseExtrapolator typing and docstring to match ZeroCutoffExtrapolator for consistency.

    [0.1.0] - 2026-06-22¶

    Added¶

    • Started tracking changes in the project.
    • Added initial implementation of the propaq library, including core functionalities and basic features.
